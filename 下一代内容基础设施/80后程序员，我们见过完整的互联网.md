# 80后程序员，我们见过完整的互联网

很多年轻程序员进入互联网行业的时候，看到的世界已经是完整的。

他们看到的是：

账号体系、App Store、云服务器、OAuth、REST API、React、Docker、Kubernetes、推荐算法、超级 App、短视频平台、SaaS，以及今天的 AI Agent。

这一切看起来理所当然：

用户就应该注册账号，内容就应该存在平台里，社交关系就应该属于平台，搜索就应该由平台提供，数据就应该上传到云端，开发者就应该调用平台开放的 API。

但问题是：

**互联网从来不是一开始就是这个样子的。**

对于很多 80 后程序员来说，我们经历的并不是“互联网的某一个阶段”。

我们几乎完整地看见了互联网从无到有、从开放到平台化、从网页到 App、从搜索到推荐，再一路走到今天的 AI。

也正因为如此，当今天重新讨论 RSS、开放 Web、个人网站、协议、Agent、数字主权这些东西时，我们看到的往往不是一个新的技术名词。

而是一条已经走了三十年的历史轨迹。

---

## 今天的互联网，是互联网唯一可能的样子吗？

不是。

甚至可以说，今天我们熟悉的互联网，只是互联网发展过程中形成的一种阶段性结构。

如果一个程序员是在移动互联网成熟以后进入行业的，他接触到的互联网通常是这样的：

```text
用户
↓
App
↓
平台账号
↓
平台数据库
↓
平台算法
↓
平台 API
```

所有东西都被包在一个产品内部，微信用户存在微信里，抖音创作者存在抖音里，小红书内容存在小红书里。

平台既控制身份，也控制内容，还控制分发、搜索、关系和商业化。

于是久而久之，我们甚至开始默认：

> 互联网就应该是这样。

但早期互联网的基本模型完全不同。

它更像：

```text
协议
↓
应用
↓
用户
```

HTTP 不属于某家公司，

SMTP 不属于某家公司，

DNS 不属于某家公司，

[RSS](https://www.rssboard.org/rss-specification) 不属于某家公司，

Email 更是最典型的例子：你用 Gmail，我用 Outlook，另外一个人自己架邮件服务器，三个人仍然可以互相通信。

这才是互联网最早期非常重要的思想：

> **互操作性先于平台。**

软件可以不同，服务器可以不同，公司可以不同，

只要大家遵守协议，就可以互相连接。

这和今天：

```text
微信只能连接微信
抖音只能连接抖音
小红书只能连接小红书
```

其实是完全不同的互联网结构。

## 80后程序员特殊在哪里？

80 后程序员真正特殊的地方，不是年龄，而是所处的时间窗口。

这一代人很可能是少数完整经历下面这条链条的人：

```text
单机软件
↓
局域网
↓
拨号上网
↓
BBS
↓
聊天室
↓
门户网站
↓
搜索引擎
↓
个人主页
↓
论坛
↓
Blog
↓
RSS
↓
Web 2.0
↓
SNS
↓
电商
↓
智能手机
↓
App
↓
移动互联网
↓
超级平台
↓
推荐算法
↓
短视频
↓
云计算
↓
SaaS
↓
AI
↓
Agent
```

这意味着什么？

意味着我们不是只知道这些技术“是什么”。

而是很多时候知道：

> **它们为什么会出现。**

为什么搜索引擎会崛起？因为网页数量开始爆炸。

为什么 RSS 有价值？因为用户需要跨网站获取更新。

为什么门户会衰落？因为搜索把信息入口重新分配了。

为什么 App 会取代大量 Web 场景？因为移动端的交互、通知、传感器和支付体系变了。

为什么超级平台越来越封闭？因为身份、关系、内容、支付和分发全部进入同一个商业闭环之后，开放反而不符合平台自身利益。

为什么推荐算法取代了订阅？因为内容供给开始超过用户主动筛选能力。

为什么今天 AI Agent 又开始重新关注开放协议？因为机器比人更不喜欢操作封闭 UI。

这一整套因果链，才是完整互联网经验真正有价值的地方。

## 很多今天所谓的新东西，其实都能找到早期互联网的影子

技术经常给人一种不断向前的错觉：

新框架、新协议、新概念、新产品。

但如果把表面的品牌和技术栈拿掉，会发现很多互联网产品其实一直在解决相同的问题。

比如：

```text
个人主页
→ Creator Page

Blog
→ Newsletter / 长内容平台

RSS
→ Follow / Feed

论坛
→ Community

IRC
→ Slack / Discord

即时通讯
→ Messenger

Web Service
→ API

Bot
→ Agent

收藏夹
→ Read Later

个人硬盘
→ Cloud Drive

个人网站
→ Digital Garden
```

它们当然不完全相同，技术能力、规模、产品体验都已经发生巨大变化，但底层问题经常高度相似。

比如 Twitter，从产品层面，它当然是一个复杂的社交网络，

但如果把它抽象一下：

```text
Source
↓
Follow
↓
New Entry
↓
Timeline
```

是不是和 RSS 极其相似？

区别只不过是 Twitter 又往上增加了：

```text
Identity
+
Social Graph
+
Reply
+
Like
+
Repost
+
Recommendation
+
Ads
+
Governance
```

于是一个开放的 Feed 模型，逐渐变成了一个完整的平台。

从这个角度看，互联网很多所谓的创新并不是彻底创造一个新问题。

而是：

> **不断在原有开放协议上增加能力，然后最终把能力封装进平台。**

---

## 真正发生变化的，是“协议互联网”变成了“平台互联网”

早期互联网的权力中心主要在协议。

比如：

```text
HTTP
SMTP
FTP
DNS
RSS
```

你可以选择不同的软件实现它们。

但今天互联网大量核心能力都已经转移到平台内部：

```text
Identity
Search
Feed
Recommendation
Payment
Social Graph
Storage
Messaging
Distribution
```

于是用户表面上拥有更多功能，实际上失去了很多迁移能力。

比如：

你关注了 1000 个抖音账号，这 1000 个关注关系是不是你的数据？

从人的直觉来看，当然是。

但你能不能：

```text
Export Following
↓
Import Another Platform
```

通常不行。

你收藏了一万条内容，这些收藏是不是你的数字资产？

从用户角度看，是。

但平台关闭之后，你还能不能访问？

不一定。

你经营了十年的账号，积累了十万粉丝，这些关系是不是你自己的用户关系？法律和产品结构上往往并不是。

这就是平台互联网非常核心的结构变化：

> **用户使用互联网，但越来越少拥有互联网中的关系。**

---

## AI 可能会重新改变这件事

有意思的是，AI 出现以后，互联网可能又开始重新需要开放协议。

原因很简单：人类可以忍受复杂 UI，Agent 不喜欢。

人可以：

```text
打开 App
↓
点搜索
↓
输入文字
↓
关闭弹窗
↓
滑动
↓
点开内容
```

但对于 Agent 来说，这是一套极其低效而且脆弱的接口。

网页稍微改版：Agent 就可能失效。

平台加验证码：Agent 就可能失效。

按钮换个位置：Agent 就可能失效。

而 RSS 呢？

```text
GET /feed.xml
```

结束。

返回结构化内容，标题是什么，作者是谁，发布时间是什么，链接在哪里，全部明确。

同样，API、[JSON Feed](https://www.jsonfeed.org/version/1.1/)、[WebSub](https://www.w3.org/TR/websub/)、[ActivityPub](https://www.w3.org/TR/activitypub/) 这些东西，本质上都比 GUI 更适合机器。

于是一个很有意思的现象出现了：

> **AI 越强，开放协议可能越重要。**

过去开放协议主要解决：

> 人和不同网站之间如何连接。

未来开放协议还要解决：

> Agent 和不同数字系统之间如何连接。

---

## AI 甚至可能让 Web 重新变成基础设施

移动互联网时代，我们曾经认为：

> App 才是终局。

网站只是下载 App 的地方，但 Agent 时代，这个逻辑可能再次变化。

因为 Web 有几个平台体系很难替代的优势：

```text
URL
开放访问
结构化文档
标准协议
跨设备
可索引
可链接
可被机器访问
```

一个拥有：

```text
Domain
Website
RSS
Sitemap
API
```

的个人数字空间，对 Agent 来说反而比一个封闭 App 账号容易理解得多。

所以今天重新讨论个人网站，并不是怀旧，

重新讨论 RSS，也不是复古，

重新讨论 Open Web，更不是因为怀念二十年前的博客时代。

而是新的技术条件可能正在重新证明：

> **开放性本身就是一种基础设施能力。**

---

## 为什么经历过整个过程的人更容易意识到这一点？

因为如果一个人只经历今天的互联网，他很容易把“现状”理解成“自然规律”。

比如：

看到微信，会认为即时通讯天然就应该依赖一个平台。

看到抖音，会认为内容分发天然就应该由算法决定。

看到 App，会认为数字服务天然就应该先注册账号。

看到云服务，会认为数据天然就应该存在厂商服务器。

但经历过早期互联网的人知道：

> 这些都只是选择，不是自然规律。

互联网可以没有推荐算法，互联网可以没有账号，网站之间可以不用统一属于同一个平台，

内容可以拥有自己的 URL，订阅关系可以存在用户自己的 Reader 中，邮件服务器可以彼此独立，却仍然能够通信。

你甚至可以拥有自己的服务器、自己的域名、自己的内容、自己的备份和自己的发布系统。

它不是理论，我们真的见过。

---

## 这也是为什么技术历史经验开始重新升值

过去十多年，程序员价值很大程度上被技术栈定义。

会不会：

```text
Java
PHP
React
Vue
Node
Docker
Kubernetes
```

经常决定一个人的市场价格。

但 AI 出现以后，“会不会使用某个框架 API”的价值正在迅速下降。

Codex 可以帮你写 React，可以帮你配置 Nginx，可以帮你写 SQL，可以帮你搭 Kubernetes，

那么程序员真正剩下什么？

越来越重要的可能是：

> **知道为什么需要这些东西。**

什么时候应该前后端分离？

什么时候根本不应该分离？

什么时候需要消息队列？

什么时候一个 Cron 就够了？

什么时候需要微服务？

什么时候单体反而更正确？

什么时候应该做 App？

什么时候一个 Web 页面已经足够？

什么时候需要平台？

什么时候一个协议更好？

这些判断，很难通过背 API 获得。

它们来自：

> 时间、失败、工程经验以及对技术演变的理解。

---

## 80后程序员真正拥有的，不是旧技术，而是完整的坐标系

所以，“80 后程序员可能是最后一代见过完整互联网的人”并不是在强调资历，更不是说年轻程序员不行。

年轻一代拥有更好的工具、更强的抽象层和更高的生产效率。

真正的问题是：

> 每一代程序员进入行业的时候，所看到的互联网起点不同。

而 80 后这一代恰好站在一个非常特殊的时间窗口，我们见过互联网还没有成为互联网的时候。

见过第一次打开网页，见过第一次使用搜索引擎，见过论坛如何繁荣，见过 Blog 如何兴起，见过 RSS 为什么重要，

见过社交网络出现，见过 App 如何吞掉 Web，见过平台如何掌握分发，见过算法如何重新组织注意力，

也正在亲眼看见 AI 开始重新改造这一切。

所以这一代真正值得保留的并不是：

> “我以前会写 ASP、PHP、Delphi。”

这些技术都会过时，

真正稀缺的是：

> **我们拥有一张互联网如何一步一步走到今天的完整地图。**

知道它从哪里来，知道为什么发生变化。

也因此更容易判断：

> 接下来它可能往哪里走。

或许再过几年，人们会发现，AI 时代最有价值的一批程序员，不一定是最熟练掌握最新框架的人。

而是那些既理解新技术，又记得互联网最初为什么要设计成开放网络的人。

因为未来真正需要重新回答的问题可能不是：

> 下一个框架是什么？

而是：

> **我们到底想要一个什么样的互联网？**
