# 互联网的轮回：我们正在重新发明二十年前的东西

互联网看起来一直在向前：

新的 App，新的平台，新的协议，新的模型，新的 Agent，新的基础设施。

每隔几年，整个行业都会出现一批“全新的概念”。

但如果把名字、品牌、技术栈和商业包装拿掉，会发现一个很有意思的现象：

**互联网其实一直在重复解决同一批问题。**

人如何发布信息？人如何找到信息？人如何订阅一个人？人如何建立身份？

人如何保存自己的数据？不同软件之间如何通信？内容到底属于谁？关系到底属于谁？

过去三十年，技术发生了巨大的变化，但这些问题没有消失。

很多时候，我们只是：

> **先用开放协议解决一次，再用平台重新解决一次，现在又准备借助 AI 和 Agent 再解决一次。**

互联网不是简单地向前发展，它更像一个巨大的螺旋，不断前进，也不断回到原点。

---

## 为什么二十年前的技术，今天又开始变得重要？

[RSS](https://www.rssboard.org/rss-specification) 是一个很典型的例子。

二十多年前，RSS 解决的问题非常简单：

> 我喜欢很多网站，但我不想每天挨个打开看看它们有没有更新。

于是网站提供：

```text
feed.xml
```

用户把这个地址交给 RSS Reader，Reader 定期检查，如果网站更新：

```text
Publisher
↓
RSS
↓
Reader
↓
User
```

没有推荐算法，没有平台账号，没有关注按钮，没有统一的信息流平台。

用户自己决定：

> 我订阅什么。

网站自己决定：

> 我发布什么。

RSS 只负责把两者连接起来。

后来，RSS 逐渐退出普通用户视野。

因为 Facebook、Twitter、微博、公众号、抖音、小红书出现了。

订阅关系被平台接管，信息流也被平台接管。

原来的：

```text
我订阅信息源
```

逐渐变成：

```text
我关注平台账号
```

看起来只是换了一个按钮，实际上背后的结构发生了巨大变化。

RSS 的订阅关系存在 Reader 里，平台的关注关系存在平台数据库里。许多 Reader 可以通过 [OPML](https://opml.org/spec2.opml) 导入、导出订阅列表，而平台关注列表通常无法自由迁移。

RSS 不决定你看什么，平台越来越决定你看什么。

于是我们用更强大的产品体验，交换了更弱的数据控制权。

---

## 互联网的很多创新，本质上是“开放协议 → 平台封装 → 再开放”

可以把互联网过去几十年的变化简化成三步。

第一阶段：

> **协议解决问题。**

第二阶段：

> **平台把协议包装成产品。**

第三阶段：

> **平台变得过于封闭以后，人们又开始寻找开放方案。**

RSS 就是如此，Email 也是如此，即时通讯也是如此，个人网站也是如此。

甚至今天的 AI Agent，也开始出现同样的循环。

---

## 第一轮：个人主页 → 社交主页 → 个人网站重新回来

早期互联网，每个人想表达自己，最自然的方法是：

> 做一个个人主页。

可能很丑，可能只有几张 GIF，可能有访问计数器，可能背景音乐自动播放，

但它有一个非常重要的特点：

> **这是我的地址。**

```text
example.com/zhangsan
```

后来个人主页逐渐被平台主页取代：

MySpace，Facebook，博客，微博，公众号，知乎，小红书，抖音。

建立一个个人主页越来越容易，但这个“主页”已经不再真正属于个人。

你的地址变成：

```text
platform.com/user/123456
```

你的内容、粉丝、互动、身份都依赖平台。

今天，“个人网站”又重新被大量人讨论。

Digital Garden、Personal Knowledge Base、Personal Website、Creator Site、个人数字花园。

甚至越来越多人重新买域名，为什么？

不是因为大家突然怀旧，而是因为经过二十年的平台化以后，人们重新意识到：

> **平台主页解决的是展示问题，个人域名解决的是所有权问题。**

于是个人主页又回来了，只是这一次，它背后有：

```text
Static Site
CMS
Git
Cloud
AI
CDN
Automation
```

形式变了，问题没变。

---

## 第二轮：RSS → Follow → Algorithm Feed → RSS 又回来

Twitter/X 的核心是什么？

把复杂功能拆掉，其实非常简单：

```text
Person
↓
Follow
↓
Post
↓
Timeline
```

这和 RSS 的：

```text
Source
↓
Subscribe
↓
Entry
↓
Reader
```

结构极其相似。

Twitter 在上面增加：

```text
Identity
Social Graph
Reply
Like
Repost
Notification
Recommendation
Ads
```

于是 Feed 从一个开放协议，变成一个平台产品。

后来算法进一步介入：

```text
Following
↓
Recommendation
↓
For You
```

用户甚至不再主要看到自己主动订阅的内容，订阅关系的重要性越来越低。

平台开始代替用户决定：

> 你应该看什么。

但今天 AI Agent 出现之后，RSS 又突然变得有价值。

为什么？因为 Agent 最讨厌 UI。

一个 Agent 如果要获取一个网站的新文章，可以：

```text
打开网页
↓
解析 DOM
↓
处理弹窗
↓
找文章列表
↓
判断新旧
↓
打开详情
```

也可以：

```text
GET /feed.xml
```

哪个更合理？答案显而易见。

于是 RSS 曾经为“人”解决的问题，开始再次为“机器”提供价值。

---

## 第三轮：IRC → QQ群 → Slack / Discord → 开放通信协议

早期 [IRC](https://datatracker.ietf.org/doc/rfc1459/) 是一种非常典型的互联网通信方式。

服务器可以不同，客户端可以不同，协议是公开的。

后来即时通信逐渐平台化：

MSN、QQ、微信、Slack、Discord，

产品体验越来越好，但通信关系也越来越封闭。

微信用户无法直接给 Telegram 用户发消息，Discord 里的 Community 也无法天然与其他系统互通。

于是，[Matrix](https://spec.matrix.org/latest/) 试图让不同通信服务器组成开放的联邦网络，[ActivityPub](https://www.w3.org/TR/activitypub/) 则把互操作的思路带到去中心化社交网络。

它们分别重新提出一个早已存在的问题：

> 为什么不同服务器上的用户和内容，不能通过共同协议彼此连接？

听起来像一个新问题，其实不是，我们只是绕了一圈。

---

## 第四轮：Blog → 平台内容 → Newsletter → Blog 又回来

Blog 曾经是 Web 最重要的内容形式之一。

作者拥有自己的：

```text
Domain
URL
Archive
RSS
```

后来内容逐渐进入平台：

Medium、知乎、公众号、微博、头条、小红书，

内容发布越来越简单，分发越来越强，但作者也越来越依赖平台，再后来 Newsletter 又开始兴起。

很多创作者重新发现：

> 我需要直接触达读者。

于是：

```text
Blog
↓
平台内容
↓
Newsletter
```

但 Newsletter 解决的，其实仍然是早期 Blog + RSS 曾经解决的问题：

> 用户如何持续收到某个创作者的更新？

形式变了，问题没有变。

---

## 为什么互联网不断重复这些循环？

因为互联网内部一直存在两股力量。

第一股力量是：

> **开放。**

开放意味着：

```text
协议
标准
可迁移
可互操作
去中心
用户控制
```

第二股力量是：

> **产品化。**

产品化意味着：

```text
更简单
更统一
更好用
更快增长
更强网络效应
更容易商业化
```

开放协议通常很自由，但产品体验不好。

平台产品通常很好用，但控制权越来越集中。

于是互联网不断摇摆：

```text
开放
↓
难用
↓
平台化
↓
好用
↓
封闭
↓
反弹
↓
重新开放
```

这就是互联网的轮回。

---

## 平台为什么容易走向封闭？

因为平台一旦规模足够大，它的商业利益往往会逐渐和开放性发生冲突。

假设用户可以轻松导出：

```text
粉丝
关注
收藏
内容
消息
社交关系
```

然后一键迁移到竞争平台，那么平台的护城河就会大幅降低。

因此平台在商业上通常有动力把这些东西锁在自己的数据库里。

原来互联网的价值是：

> Connection。

平台经济的价值越来越变成：

> Lock-in。

谁掌握：

```text
Identity
Social Graph
Content
Distribution
Payment
Data
```

谁就拥有更强的用户锁定能力。

于是互联网从：

> 网络连接协议

逐渐演化成：

> 一座座巨大的数字城市。

城市之间有高速公路。

但居民身份、房产、关系和资产很难迁移。

---

## AI 正在打破上一轮平台化的一部分逻辑

AI 最大的变化之一，是把“操作软件”的方式改了。

过去人使用软件：

```text
GUI
↓
Button
↓
Menu
↓
Form
```

于是软件公司长期竞争的是：

> 谁的界面更简单。

但是 Agent 使用软件，并不真正需要漂亮 GUI。

Agent 更喜欢：

```text
API
Protocol
Structured Data
Machine-readable Interface
```

这会产生一个非常深远的变化。

过去：

> GUI 是产品。

未来越来越可能：

> **协议本身就是产品能力。**

比如一个网站如果有：

```text
RSS
JSON Feed
Sitemap
API
Structured Metadata
```

Agent 就可以很容易理解它。

反之，一个内容全部锁在 App 内、只有复杂 UI 的平台，即使对人很好用，对 Agent 也可能意味着更高的访问成本和更脆弱的自动化流程。

于是开放 Web 可能获得一个新的用户：

> **AI。**

过去开放 Web 是给浏览器看的，未来开放 Web 同时是给 Agent 看的。

---

## AI 甚至可能让“个人网站”重新升级

过去个人网站的问题是：

> 没流量。

所以用户迁移到平台。

但未来如果大量信息消费由 Agent 参与，情况可能不同。

比如用户告诉 Agent：

> 帮我找过去一个月关于个人数字主权最有价值的文章。

在访问授权和站点规则允许的前提下，Agent 不一定首先需要平台推荐。

它可以：

```text
RSS
Search
Sitemap
Open Web
Knowledge Graph
```

自主寻找。

如果一个创作者拥有：

```text
自己的域名
自己的内容
结构化 Metadata
RSS
Sitemap
开放 API
```

他的内容反而更容易被 Agent 理解。

这意味着：

> **个人网站未来的访问者，可能不只是人。**

还有 Agent。

这会重新改变 Web 的价值。

---

## “平台入口”可能再次变成“协议入口”

过去十多年，一个创业产品经常首先思考：

```text
做 App
做小程序
做公众号
做平台账号
```

未来可能越来越需要先思考：

```text
我的数据接口是什么？
我的 Agent 能怎么访问？
我的内容如何被机器发现？
有没有 Feed？
有没有 API？
能不能导出？
有没有标准格式？
```

也就是说：

> 产品正在重新面对二十年前互联网面对的问题。

不同系统如何互联？

数据如何交换？

用户如何拥有身份？

关系如何迁移？

内容如何被发现？

只不过这次参与互联网的不只有人。

还有 Agent。

---

## Local-first 也是一种轮回

云计算时代，行业长期强调：

> Everything in the Cloud。

文件上云，数据库上云，照片上云，笔记上云，软件变 SaaS，甚至身份也存在云端。

但随着 [Local-first](https://www.inkandswitch.com/essay/local-first/) 概念重新进入技术讨论，人们又开始追问本地数据所有权，原因并不复杂。

当所有东西都放在别人的服务器上以后，人们重新发现：

```text
离线怎么办？
服务关闭怎么办？
账户被封怎么办？
价格上涨怎么办？
公司倒闭怎么办？
数据迁移怎么办？
隐私怎么办？
```

于是开始出现：

```text
Local-first
Offline-first
Self-hosting
Personal Server
Personal Cloud
```

这是不是很像过去的：

> 本地软件？

是，但又不完全一样。

新的 Local-first 是：

```text
Local Ownership
+
Cloud Sync
+
Open Protocol
+
Multi-device
```

这就是所谓的螺旋式轮回，不是回到过去。

而是：

> 带着新能力回到旧问题。

---

## 互联网真正轮回的不是技术，而是控制权

如果只看技术名词，很容易觉得：

> RSS 和 Twitter 完全不是一个时代的产品。

> BBS 和 Discord 没什么关系。

> 个人主页和 Creator Economy 没关系。

但如果看控制权，就会发现一条非常清晰的线。

早期：

```text
用户控制客户端
网站控制内容
协议连接双方
```

后来：

```text
平台控制客户端
平台控制内容
平台控制关系
平台控制分发
```

现在：

```text
用户重新要求
Own Data
Own Identity
Own Content
Own Sources
Own Agent
```

所以真正的轮回其实不是：

> 某种旧技术重新流行。

而是：

> **互联网的控制权正在反复在用户和平台之间摆动。**

---

## 这也是个人数字主权真正出现的背景

个人数字主权并不是突然创造出来的一个概念，它实际上是过去二十多年平台化发展积累出来的反作用力。

当越来越多东西进入平台以后：

```text
身份
内容
数据
关系
支付
资产
订阅
收藏
阅读记录
```

用户开始重新问：

> 哪些东西应该真正属于我？

比如 RSS Reader，表面上它只是一个阅读软件，但从数字主权角度看，

它保存的是：

```text
我关注谁
我长期读什么
我收藏什么
我认为哪些内容重要
```

这其实是一个人的：

> **信息输入关系。**

如果这些东西全部存在某个平台数据库里，那么平台掌握的已经不只是内容。

而是：

> 你的注意力结构。

所以未来的个人数字主权，不应该只讨论：

```text
文件归我
照片归我
文章归我
```

还需要讨论：

```text
我的身份
我的关系
我的订阅
我的阅读历史
我的知识库
我的 Agent
```

---

## 技术没有回到过去，而是在更高一层重新开始

所以今天重新看到：

RSS、个人网站、自托管、Local-first、开放协议、ActivityPub、去中心化身份、Agent Protocol，

并不意味着互联网失败了三十年以后准备重新回到 2005 年，恰恰相反。

真正发生的是：

> **过去的问题，在新的技术条件下又需要被重新回答。**

二十年前 RSS 很好，但普通用户嫌麻烦，今天 AI 可以自动发现 RSS。

二十年前个人网站维护困难，今天 Agent 可以帮你部署。

二十年前自托管服务器门槛很高，今天自然语言就可以完成大量运维。

二十年前开放协议用户体验差，未来 Agent 可以隐藏协议复杂性。

于是过去开放互联网最大的问题：

> 难用。

有机会被 AI 大幅降低，这可能是一个非常关键的变化。

因为如果：

```text
开放
```

第一次可以同时做到：

```text
好用
```

那么平台化过去二十年的一个重要优势，就会开始被削弱。

---

互联网从来没有简单地从旧时代走向新时代，它更像不断摆动的钟摆，

开放、集中、平台化、封闭、再开放。

每一次回来，都不是回到原点。

而是带着新的基础设施、新的计算能力和新的使用者，再次回答那些古老的问题。

今天站在 AI 和 Agent 的起点，我们或许正在进入互联网的下一轮循环。

而这一轮真正值得观察的，并不是：

> 下一个超级 App 是谁？

而是：

> **当使用互联网的不再只有人类，开放协议、个人网站和数据所有权，会不会重新成为互联网最重要的基础设施？**
